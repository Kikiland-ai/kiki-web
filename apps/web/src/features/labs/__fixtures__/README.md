# Synthetic Python execution receipt

`python-execution.json` was generated from the actual pinned backend offline pipeline at `73c6e96ab876ad3a400e76110bcf4abac9dbce60`. All findings are unknown, identities are random test IDs, and no images, Firebase tokens or learner records are included. Vitest uses it to verify Python full states, committed projections and fragmented multilingual SSE. It is excluded from production imports.

Regeneration from the repository root:

```sh
KIKI_BACKEND_CHECKOUT=/path/to/kiki-backend apps/api/.venv/bin/python apps/api/scripts/export_lab_execution_receipt.py
```

The isolated browser acceptance executable additionally supplies controlled matches for a procedure action; it never passes a criterion, writes practical grades or calls a real provider.


`lab-input-requirements.json` is a public authored-contract test projection from backend `f2dca8b806e4002411b5704e19f0f40681093298`, bound to the same definition hash as the execution receipt. Its source snapshots are `apps/api/tests/lab-input-definition.json` and `lab-input-policy.json` (the latter intentionally contains only schema, conditions, response kinds and prompts). The API test regenerates an independent ignored requirements receipt consumed by `check-python-learning.mjs`. Neither fixture nor the `/tests/lab-input/` synthetic UI harness is imported by the production entry. Browser tests for that harness make no backend/provider/auth/capture calls.
